1. מה המוצר

costats היא אפליקציית מגש (tray) ל-Windows, כתובה ב-WPF / .NET 10, שמציגה בזמן אמת את מצב המכסות, הטוקנים וההוצאות של כלי קידוד מבוססי AI: Codex, Claude Code, GitHub Copilot (ניסיוני) ו-Z.ai. זו המקבילה הווינדוסית ל-CodexBar של macOS.

הקוד בתיקייה הוא העתק של הפרויקט הפתוח fmdz387/costats (רישיון MIT). בסעיף 7 מפורט מה זה מחייב.

2. יכולות

תצוגת שימוש

  • ניצול סשן ושבועי, טיימר איפוס ו"קצב" (pace)
  • טוקנים + עלות יומי ו-30 יום
  • יתרת קרדיט / חריגה (overage) כשזמינה

חוויית משתמש

  • ווידג'ט "זכוכית" (Mica/Acrylic) מהמגש
  • מקש קיצור גלובלי Ctrl+Alt+U
  • הפעלה בכניסה, מופע יחיד, הגדרות ב-%LOCALAPPDATA%\costats\settings.json

עדכון עצמי

  • בדיקה מול GitHub Releases כל 6 שעות
  • אימות SHA-256, החלפה עם גיבוי ו-rollback
  • תמיכה ב-MSIX/AppInstaller

הפצה ובונוס

  • התקנה ב-PowerShell one-liner, בינארים x64+arm64
  • CI ו-Release ב-GitHub Actions
  • CLI ב-Node: npx costats ccinsights — מרנדר כרטיס Insights של Claude Code (Playwright)

4. ארכיטקטורה

Clean Architecture בארבע שכבות, כ-10,000 שורות C#:

פרויקטתפקיד
costats.Coreמודלים טהורים: PulseState, ProviderReading, QuotaWindow, TokenLedger, TrayStatusComposer
costats.Applicationה"לב": PulseOrchestrator (BackgroundService), SourceSelector, הפשטות (ISignalSource, ICredentialVault, ISettingsStore)
costats.Infrastructureמימושי ספקים, סורק לוגים, Credential Vault, Glass backdrop
costats.AppWPF: חלונות, ViewModels, tray host, hotkey, עדכון עצמי, DI ב-App.xaml.cs

זרימה

  1. PulseOrchestrator רץ בטיימר (ברירת מחדל 5 דקות) או לפי טריגר ידני.
  2. לכל ספק יש כמה ISignalSource; SourceSelector בוחר את הקריאה האמינה ביותר לפי ReadingConfidence (OAuth > CLI > לוגים).
  3. הקריאות רצות סדרתית (כדי לא להריץ סריקות קבצים כבדות במקביל), מתמזגות ל-PulseState ומשודרות כ-IObservable ל-ViewModels; snapshot נכתב ל-JSON.
הוספת ספק חדש = מימוש ISignalSource אחד ורישום ב-DI. זו נקודת הרחבה נקייה.

5. איכות ותחזוקה

  • בדיקות: פרויקט costats.Core.Tests מכסה פרסרים (Codex app-server, Z.ai, Claude subscription) ואת TrayStatusComposer. אין בדיקות ל-UI, ל-orchestrator או לעדכון העצמי.
  • CI: build + test ב-Debug וב-Release על windows-latest; workflow נפרד ל-release.
  • גרסאות: מקור אמת יחיד ב-src/Directory.Build.props (1.4.6), סקריפט bump-version.ps1.
  • קבצים גדולים: StartupUpdateCoordinator.cs (~970 שורות), UsageLogScanner.cs (~720), LogDigestor.cs (~620) — מועמדים לפיצול.

6. חולשות וסיכונים

#סיכוןחומרההסבר
1תלות ב-APIs לא רשמייםגבוההה-usage endpoints של Claude/Codex/Copilot אינם מתועדים ועלולים להישבר בלי התראה. ה-README מציין זאת במפורש לגבי Copilot.
2מחירון מוטמע בקודבינוניתכל שינוי מחיר או מודל חדש דורש עדכון קוד ושחרור גרסה; הערכות העלות עלולות להיות לא מדויקות.
3גישה לאישורים רגישיםבינוניתהאפליקציה קוראת קבצי OAuth. אין טלמטריה, אך המשתמש חייב לסמוך על הבינארי ועל מנגנון העדכון.
4כיסוי בדיקות חלקיבינוניתהקוד המורכב והמסוכן ביותר (החלפת בינארי בזמן ריצה) אינו מכוסה.
5Windows בלבד, .NET 10נמוכהדורש SDK עדכני; אין גרסת macOS/Linux (מפנים ל-CodexBar).

7. השלכות על הריפו שלך

העדכון העצמי מצביע על הריפו המקורי. ב-appsettings.json: "Repository": "fmdz387/costats", ועוד כ-97 קבצים מפנים ל-fmdz387/costats (סקריפטי התקנה ופרסום, AppxManifest, README). כרגע גרסה שתבנה אצלך תוריד עדכונים מהפרויקט המקורי ותדרוס את עצמה.

  • רישיון: MIT על שם fmdz — פורק ציבורי מותר, בתנאי שקובץ ה-LICENSE והקרדיט נשמרים. מומלץ להוסיף ל-README "Fork of fmdz387/costats".
  • מיתוג: שם הריפו (ai-usage-tray) שונה משם המוצר (costats). כדאי להחליט אם זה פורק-המשך או מוצר חדש.
  • סביבה מקומית: קיימים אצלך ~/.claude/.credentials.json ו-~/.codex/auth.json, כך שהאפליקציה אמורה להציג נתונים מיד אחרי dotnet build.
  • מצב git: הקבצים עדיין לא עברו commit ולא נדחפו.

8. המלצות

  1. להחליט: פורק נאמן (שומר שם ומנגנון עדכון מול המקור) או מוצר עצמאי (להחליף את כל ההפניות ל-ShlomiPorush/ai-usage-tray, לשנות Update.Repository, סקריפטים ו-manifest).
  2. להוסיף שורת שיוך ב-README ולשמור LICENSE.
  3. לבנות ולהריץ מקומית (dotnet build .\costats.sln -c Release) כדי לאמת שה-endpoints עדיין עובדים.
  4. אם מפתחים הלאה: להוסיף בדיקות ל-PulseOrchestrator ולעדכון העצמי, ולהוציא את המחירון לקובץ תצורה.
