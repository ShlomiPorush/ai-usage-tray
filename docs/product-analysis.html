1. מה המוצר

AI Usage Tray היא אפליקציית מגש (tray) ל-Windows, כתובה ב-WPF / .NET 10, שמציגה מאחורי אייקון אחד את מצב המכסות של כמה מנויי AI לקידוד בו-זמנית: Claude, Codex (OpenAI/ChatGPT), Z.AI / GLM (אופציונלי) ו-GitHub Copilot (ניסיוני). המיקוד הוא ריבוי חשבונות: כל מספר של חשבונות Claude וכל מספר של חשבונות Codex, כשלכל חשבון תיקיית פרופיל משלו.

הפרויקט הוא פורק של fmdz387/costats (רישיון MIT) מגרסה 1.4.6. הוא שומר על הארכיטקטורה, ה-UI, מנגנון העדכון והאריזה של המקור, ומשנה את מה שמנוטר ואת אופן הקריאה. פירוט ההתאמות בסעיף 8. שמות הפרויקטים והתיקיות בקוד עדיין costats.*, וכך גם נתיב ההגדרות, כדי שהתקנות קיימות ימשיכו לעבוד.

2. יכולות

תצוגת שימוש

  • ניצול סשן (5 שעות) ושבועי לכל חשבון, עם טיימר איפוס
  • מגבלות ברמת מודל שמדווחות על ידי Claude
  • שבבי תוכנית (Max, Plus, Pro Lite) ל-Claude ול-Codex
  • הערכות עלות יומית ו-30 יום היכן שזמין

חוויית משתמש

  • ווידג'ט "זכוכית" (Mica/Acrylic) מהמגש, פתיחה בתצוגת סקירה
  • מקש קיצור גלובלי נשלט וניתן לעריכה, ברירת מחדל Ctrl+Alt+U
  • ערכת נושא בהירה/כהה, ברירת מחדל לפי Windows
  • הפעלה בכניסה, מופע יחיד, הגדרות ב-%LOCALAPPDATA%\costats\settings.json

ניהול חשבונות

  • טבלת ספקים בהגדרות עם דיאלוג הוספה/עריכה לכל חשבון
  • שינויים נכנסים לתוקף בלי הפעלה מחדש
  • חשבון ראשי (כוכב) שמכתיב את אייקון המגש
  • הגירה אוטומטית מהגדרות ישנות (ClaudeConfigDir, OpenAiAccounts)

הפצה ועדכון עצמי

  • בדיקת עדכון אוטומטית מול GitHub Releases כל 6 שעות, עם מתג בהגדרות
  • אימות SHA-256, החלפה עם גיבוי ו-rollback
  • התקנה ב-PowerShell one-liner, בינארים x64+arm64 עצמאיים
  • CLI ב-Node שהועבר מהמקור: npx costats ccinsights

3. מקורות נתונים

ספקמקורהערות
Claude
כל מספר של חשבונות		ClaudeSubscriptionSource + ClaudeOAuthUsageFetcher: endpoint ה-usage של OAuth ב-api.anthropic.com/api/oauth/usage, עם הטוקן של פרופיל CLAUDE_CONFIG_DIR ייעודי לכל חשבוןמזהי ספק claude:<id>. מדווחות מכסת סשן (5 שעות) ומכסה שבועית, וכן מגבלות ברמת מודל (מערך limits, למשל מכסה שבועית ל-Fable) שמוצגות פר חשבון. המכסה היא של המנוי כולו וכוללת שימוש מאפליקציית הדסקטופ.
Codex
כל מספר של חשבונות		CodexAppServerSource: ה-JSON-RPC המקומי הרשמי codex app-server, מתודה account/rateLimits/read, תהליך קצר-חיים לכל חשבון עם CODEX_HOME משלומזהי ספק codex:<id>. האפליקציה לא קוראת ולא מעתיקה טוקנים, שכן Codex אחראי לאימות ולרענון.
Z.AI / GLMendpoints של api.z.ai (תוכנית coding או pay-as-you-go) עם Bearer tokenמוסתר לגמרי בממשק כל עוד לא הוגדר מפתח API.
Copilotendpoint לא רשמי של GitHub, PAT קלאסי ב-Credential Managerכבוי כברירת מחדל (CopilotEnabled), ניסיוני.

ניתוח השימוש קורא מקומית לוגים של Claude ו-Codex באמצעות UsageLogCollector ו-UsageLogParser. UsageAggregator מחשב הערכת שווי לפי מחירי API גולמיים, ולא לפי חשבון המנוי בפועל. cache מקומי מאיץ סריקות חוזרות, וגודלו והניקוי שלו נשלטים בהגדרות. אין טלמטריה.

4. ארכיטקטורה

Clean Architecture בארבע שכבות, כ-13,000 שורות C#:

פרויקטתפקיד
costats.Coreמודלים טהורים: PulseState, ProviderReading, QuotaWindow, ScopedQuota, UsageSample, TrayStatusComposer
costats.Applicationה"לב": PulseOrchestrator (BackgroundService), SourceSelector, IAccountSourceRegistry, הפשטות (ISignalSource, ICredentialVault, ISettingsStore), AppSettings
costats.Infrastructureמימושי ספקים ו-AccountSourceRegistry, סורק לוגים, Credential Vault, Glass backdrop
costats.AppWPF: חלונות, ViewModels, tray host, hotkey, עדכון עצמי, DI ב-App.xaml.cs

זרימה

  1. PulseOrchestrator רץ בטיימר (ברירת מחדל 5 דקות) או לפי טריגר ידני.
  2. המקורות פר-חשבון נבנים ב-AccountSourceRegistry מתוך AppSettings.GetEffectiveAccounts(): לכל חשבון Codex נוצר CodexAppServerSource ולכל חשבון Claude נוצר ClaudeSubscriptionSource עם ה-fetcher של הפרופיל שלו.
  3. שמירת ההגדרות קוראת ל-Reload() של הרג'יסטרי, שמחליף את רשימת המקורות אטומית, ולכן הוספה, עריכה או הסרה של חשבון נכנסות לתוקף חי, בלי הפעלה מחדש. רענון שכבר רץ ממשיך עם ה-snapshot שלו.
  4. לספק שיש לו כמה ISignalSource, SourceSelector בוחר את הקריאה האמינה ביותר לפי ReadingConfidence (OAuth > CLI > לוגים).
  5. הקריאות רצות סדרתית, מתמזגות ל-PulseState ומשודרות כ-IObservable ל-ViewModels. לא נשמר snapshot של המכסות בדיסק.
הוספת ספק חדש = מימוש ISignalSource אחד ורישום ב-DI; הוספת סוג חשבון חדש = ענף נוסף ב-AccountSourceRegistry. שתי נקודות ההרחבה נקיות.

5. ממשק המשתמש

  • סקירה תחילה: הווידג'ט נפתח על תצוגת סקירה עם כרטיס לכל חשבון, בגודל שמתאים למספר החשבונות בפועל; לחיצה על כרטיס פותחת את תצוגת הפירוט של אותו חשבון.
  • אייקון המגש: מציג את אחוז הניצול כמספר, בארבע רצועות צבע קבועות לפי האחוז בלבד (TrayStatusComposer). מעבר עכבר פותח פופ-אפ מעוגן לאייקון שמפרט את כל החשבונות.
  • חשבון ראשי: כוכב בטבלת הספקים בהגדרות (PrimaryAccountId). כשמוגדר, הוא זה שמכתיב את אייקון המגש והכרטיס שלו מוצמד לראש הסקירה; אחרת האייקון משקף את החלון הגרוע ביותר מבין כל החשבונות.
  • ערכת נושא: system / light / dark (Theme), ברירת מחדל לפי ערכת האפליקציות של Windows.
  • הגדרות: טבלת ספקים אחידה עם דיאלוג הוספה/עריכה לכל חשבון (בורר תיקייה ל-ConfigDir), הסרה, ומפתחות Z.AI/Copilot.
  • שליטה: הצגת זמני איפוס על כרטיסי הסקירה, קיצור מקשים גלובלי ובדיקות עדכון אוטומטיות נשלטים בהגדרות. פאנל הטקסט הצמוד לשעון הוסר.

6. איכות ותחזוקה

  • בדיקות: tests/costats.Core.Tests (xunit): 379 בדיקות עוברות, כולל מקורות Claude ו-Codex, פרסרים, analytics, הגירה מהפורמט הישן, רענון מותנה ו-TrayStatusComposer.
  • CI: ירוק על windows-latest, build + test ב-Debug וב-Release.
  • Release: workflow נפרד שמפרסם ZIP עצמאי ל-win-x64 ול-win-arm64, כל אחד עם קובץ .sha256 לאימות (אין חתימת קוד, ולכן SmartScreen עשוי להתריע).
  • גרסאות: מקור אמת יחיד ב-src/Directory.Build.props (2.3.0), סקריפט bump-version.ps1; קו הגרסאות עצמאי מהמקור.
  • ניקוי: שכבת Multicc, מסלולי provider לא מחווטים, מודלי עלות ישנים ושמירת pulse snapshot הוסרו.

7. חולשות וסיכונים

#סיכוןחומרההסבר
1תלות ב-APIs לא מתועדיםגבוההה-usage endpoint של Claude אינו API ציבורי מתועד ועלול להשתנות בלי התראה; אותו דבר לגבי ה-endpoint של Copilot. הצד של Codex נשען על ממשק מקומי רשמי ולכן חשוף פחות, אך גם הוא יכול להשתנות בין גרסאות CLI.
2מחירון מוטמע בקודבינוניתהערכות העלות מחושבות לפי טבלת מחירים בקוד; כל שינוי מחיר או מודל חדש דורש עדכון קוד ושחרור גרסה, ובינתיים ההערכה עלולה להיות לא מדויקת.
3גישה לקבצי אישורים מקומייםבינוניתעבור Claude האפליקציה קוראת את טוקן ה-OAuth מתיקיית הפרופיל. אין טלמטריה, אך המשתמש חייב לסמוך על הבינארי ועל מנגנון העדכון. (עבור Codex אין קריאת טוקנים כלל.)
4אין בדיקות לעדכון העצמיבינוניתהקוד המסוכן ביותר (החלפת בינארי בזמן ריצה עם גיבוי ו-rollback) אינו מכוסה בבדיקות. בדיקות אוטומטיות פעילות כברירת מחדל, אך המשתמש יכול לכבות אותן.
5ריבוי תהליכי codex app-serverנמוכהכל רענון מריץ תהליך קצר-חיים לכל חשבון Codex; עם הרבה חשבונות זו עלות זניחה אך מורגשת, ותלויה בכך ש-Codex מותקן ומחובר בכל פרופיל.
6Windows בלבד, .NET 10נמוכהדורש SDK עדכני לבנייה; אין גרסת macOS/Linux (מפנים ל-CodexBar).

8. מצב נוכחי מול המקור

כל הפערים שזוהו בייבוא הראשוני נסגרו: העדכון העצמי, המיתוג, השיוך והפרסום מיושרים לריפו הזה, והקוד מחויב ומשוחרר ב-GitHub.
  • עדכון עצמי: ב-appsettings.json תחת Costats:Update: "Enabled": true, "Repository": "ShlomiPorush/ai-usage-tray". המשתמש שולט בבדיקות האוטומטיות דרך AutomaticUpdateChecksEnabled.
  • מיתוג ואריזה: הבינארי הוא AIUsageTray.exe, שם המוצר "AI Usage Tray", והנכסים הם ai-usage-tray-win-x64-vX.Y.Z.zip / -arm64; סקריפטי ההתקנה והפרסום ו-manifest מפנים לריפו הזה. ההתקנה היא per-user ל-%LOCALAPPDATA%\AIUsageTray\app.
  • רישיון ושיוך: קובץ ה-LICENSE (MIT) שומר את הודעת זכויות היוצרים של המקור, וה-README פותח בשורת "fork of fmdz387/costats" ומכיל טבלת השוואה מפורשת מול המקור וסעיף קרדיטים.
  • תאימות לאחור: נתיב ההגדרות נשאר %LOCALAPPDATA%\costats\settings.json ושמות הפרויקטים נשארו costats.*, כדי לא לשבור התקנות קיימות ולהקל על מיזוג שינויים עתידיים מהמקור.
  • קוד לא מחווט: מסלולי provider ישנים ושכבת Multicc הוסרו כדי שמפת הקוד תשקף רק התנהגות חיה.

9. המלצות

  1. להוסיף בדיקות ל-PulseOrchestrator ולמסלול העדכון העצמי (במיוחד ה-rollback), שהם כיום הקוד הפעיל הכי פחות מכוסה.
  2. להמשיך להציג את חישוב העלות כהערכת מחיר API בלבד, ולעדכן את מחירון ברירת המחדל ואת pricing.json לפי הצורך.
  3. להוסיף בדיקות UI אוטומטיות להגדרות החדשות ולמצבי light ו-dark.
  4. לעטוף את הקריאה ל-endpoint של Claude בבדיקת רגרסיה על מבנה התשובה (כולל מערך limits), כדי לזהות שינוי סכימה מהר.
