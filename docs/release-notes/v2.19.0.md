## What's changed

**The tray icon is visible on Windows 11.** Windows 11 puts new tray icons in the hidden icons menu, so the app could look like it was not running. It now shows its icon on the taskbar the first time it starts. If you later move the icon back into the hidden menu yourself, the app leaves your choice alone.

**Move your settings to another computer.** Settings > General has a new **Move to another computer** section with **Export settings** and **Import settings**. The file carries your accounts and preferences. Account folders are adjusted to the new computer's user profile, and any folder that is not found is listed after the import. API keys, tokens and the remote view link are never included, so sign in to Claude and Codex again on the new computer.

**Codex is found wherever it is installed.** Earlier versions only looked for the standalone Codex installer, so Codex installed with npm, or only available on PATH, showed every Codex account as "not installed". The app now finds it in all of these places. If you had turned on automatic Codex five-hour window start, it will now actually run within your schedule.

**Debug logging for troubleshooting.** Settings > General has a **Debug logging** switch that records in detail what the app does, in a separate log, to help find problems. **Open log folder** takes you to it. The log never contains keys, tokens or your remote view link. It turns itself off after seven days, and the log is deleted whenever debug logging turns off.

**App data has a new home.** Settings, logs and caches move from `%LOCALAPPDATA%\costats` to `%LOCALAPPDATA%\AIUsageTray` automatically on the first start. Nothing needs to be set up again. If you ever go back to an older version, move these files back first, or the older version will start without your settings.

**Cleaner rounded windows on Windows 11.** The Settings and onboarding windows no longer show a second, squarer outline around their corners, which was most visible in the dark theme.

## Known issue

Codex accounts with **Keep session active** can briefly show "Sign-in required" and send a sign-in notification while the account is actually still signed in. The next refresh shows the account as connected again. A fix is in progress.
