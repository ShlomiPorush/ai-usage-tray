# Agent guidelines for ai-usage-tray

Read this before touching anything. It exists because agents have already broken this project by ignoring these rules.

## What this is

AI Usage Tray: a .NET 10 WPF Windows tray app (fork of fmdz387/costats, MIT) showing quota usage for Claude, OpenAI Codex, Z.AI and Copilot accounts, plus a remote web viewer at https://ai.yaaps.net. The primary relay is the containerized Node.js/SQLite server under `remote/server`; the Cloudflare Worker is retained as a rollback implementation.

## Hard rules

1. **Never add AI attribution.** No "Co-Authored-By: Claude", no "generated by" notes, anywhere: commits, code, docs, UI text.
2. **Never use em-dash characters** (U+2014) in anything you write: code comments, docs, UI strings, commit messages.
3. **Quota data is canonical USED percent internally.** Used is the default display. A user may choose remaining instead; when they do, every visible number and progress-bar fill must follow that choice on desktop and web surfaces. Bands still come from canonical used percent through `UsageBands` in `costats.Core`: green 0-49 `#10B981`, yellow 50-74 `#EAB308`, orange 75-89 `#F97316`, red 90-100 `#EF4444`, identical in both themes. This preserves the meaning that green has capacity and red is near exhaustion even when the displayed number is remaining. A provider-reported severity (`QuotaSeverity`) is carried in the models and remote payload but colours nothing; do not reintroduce it as a colour or status override.
4. **The live Codex monitoring path is `CodexAppServerSource`** (local `codex app-server` JSON-RPC via `CodexAppServerClient`/`CodexAppServerRateLimitParser`). Opt-in five-hour-window activation is a separate session action through the official Codex CLI; it is never a quota source and must remain ephemeral, read-only, configured with approval policy `never`, isolated from rules and user config, web-disabled, shell-tool-disabled, and stripped of inherited shell environment variables. `CodexLogSource`, `CodexOAuthUsageFetcher`, `ClaudeLogSource`, `MulticcClaudeLogSource` are UNWIRED legacy kept for upstream merges. Check `AccountSourceRegistry` + `App.xaml.cs` DI before assuming a file runs. An agent once implemented a whole feature in dead files; nobody saw it.
5. **Never read or copy provider tokens for Codex.** Codex owns its auth. Quota monitoring only talks to the local app-server. The opt-in activation path may pass the monitored account's `CODEX_HOME` to the official Codex CLI, but must not inspect, copy, log or persist its credentials. This local monitoring rule is Codex-specific: Codex has a local `codex app-server` to ask, Claude does not. **Claude's live path is the Anthropic OAuth API by design** (since the upstream fork): the token is read from each account's own `.credentials.json`, quota comes from `/api/oauth/usage`, and identity plus the current plan come from `/api/oauth/profile`. Do not treat the plan fields inside `.credentials.json` as current (they are a login-time snapshot, kept only as fallback) and do not "fix" the Claude path to be local-only. Never log or commit tokens; `local/` and credential files are git-ignored.
6. **Do not commit, tag, release or push unless explicitly asked.** The owner (or the managing agent) does integration.
7. **Do not promise visible UI results without verifying** against live data first. Provider APIs change between calls (e.g. Codex `rateLimitsByLimitId` appears intermittently; Claude percentages move constantly).
8. Keep replies to the owner short: outcome first, few lines, act instead of describing. Hebrew for chat, English for code/docs/commits.
9. **Session activation is explicit opt-in and defaults off.** Do not enable or run live activation during automated tests or routine review: it creates provider activity and may start a real quota window. Test command construction, preflight and state handling with fakes. A live activation check requires explicit owner approval.

## Build, test, verify (all local; do NOT use CI as your build machine)

- SDK: `"%LOCALAPPDATA%\dotnet-sdk\dotnet"` (a user-local .NET 10 SDK; the system has none).
- Build: `"%LOCALAPPDATA%\dotnet-sdk\dotnet" build costats.sln -c Release` (zero errors AND zero warnings expected).
- Test: same exe, `test costats.sln -c Release --no-build`. All tests must pass. Add tests for parser/composer changes.
- Remote server test: `node remote/server/server.test.mjs` (all tests must pass).
- JavaScript check: `node --check web/app.js` and `node --check web/sw.js` after viewer changes.
- Publish: `publish src/costats.App/costats.App.csproj -c Release -r win-x64 -o <dir>`.
- Local deploy: `Stop-Process -Name AIUsageTray -Force` first (the exe locks), copy over `%LOCALAPPDATA%\AIUsageTray\app\`, relaunch. Settings live outside that folder and survive.
- Visual check: run the exe once with `--screenshot "<path with quotes>"` (quotes matter, the profile path has a space); it opens the widget, waits ~15s, saves a PNG and exits. Look at the PNG.
- What the app actually parsed: `%LOCALAPPDATA%\costats\snapshots\` (pulse snapshot JSON) and `%LOCALAPPDATA%\costats\logs\`.

## Architecture map (30 seconds)

- `costats.Core`: pure models (`UsagePulse`, `ScopedQuota`+`QuotaSeverity`, `TrayStatusComposer`, `RemoteSnapshotComposer`). Unit-testable, no IO.
- `costats.Application`: `PulseOrchestrator` (timer + refresh), `IAccountSourceRegistry`, `AppSettings` (+ legacy migration in `GetEffectiveAccounts`).
- `costats.Infrastructure`: providers. Live sources: `ClaudeSubscriptionSource` (per-account OAuth profile), `CodexAppServerSource`, `ZaiUsageSource`, `CopilotPersonalSource`. `AccountSourceRegistry` rebuilds account sources on settings save, so changes apply live; no restart flows.
- `costats.App` (WPF): `TrayHost` (icon, hover popup, positioning), `GlassWidgetWindow` (overview-first widget; the hidden overview panel reserves layout height so the window never resizes between overview and detail), `SettingsWindow` + `AddAccountWindow` dialog, `RemoteViewUploader`, `ThemeService` (light/dark via swapped ResourceDictionaries; use `DynamicResource` theme brushes, never hardcoded colours).
- `web/`: vanilla static viewer + PWA. `remote/server/`: primary Node.js/SQLite relay and static host. `remote/worker/`: Cloudflare Worker rollback implementation; `worker.bundle.js` is GENERATED by `node bundle.mjs` and embeds all of `web/`. **Any change under `web/` or `worker.js` requires regenerating the bundle**, or the rollback artifact silently stays stale. Bump the cache name in `web/sw.js` when the shell changes. The container workflow runs only when a file copied by `remote/server/Dockerfile` changes, and not for desktop release tags. **Every change to those image inputs, including `web/`, `remote/shared/`, and the copied runtime files under `remote/server/`, must increment `remote/server/VERSION` in the same change and update the pinned image tag in `remote/server/README.md`**. Never publish changed container content under an existing semantic version. The owner pastes the bundle into the Cloudflare dashboard manually when the Worker is used.
- Remote payload contract lives in `RemoteSnapshotComposer` (schema v2: windows carry `scope` and `severity`, accounts carry `blocked`). Both relay implementations store payloads verbatim with a 7-day TTL. Keep validation, routes, security headers, ID derivation and demo behavior compatible between `remote/server` and `remote/worker`.
- Remote ids are split (protocol v2): the app keeps a secret **write id** (`AppSettings.RemoteViewId`) for `PUT`/`DELETE`, and the share link carries a **read id** derived from it in `costats.Core/RemoteView/RemoteViewIds.cs`. Derivation, routes and the authoritative test vector: `remote/worker/README.md`.

## Release flow (owner-approved only)

Bump `VersionPrefix` in `src/Directory.Build.props` (single source of truth) -> commit -> tag `vX.Y.Z` -> push tag. The Release workflow builds x64+arm64 ZIPs with `.sha256` and publishes; the app self-updates from this repo's releases. Verify release readiness via the public download URL, not the GitHub API (rate limits).

- Write `CHANGELOG` entries and release notes in clear, human language. Explain what changed, why it matters to users, and any important limitation. Do not publish raw commit subjects, merge lines, PR numbers, or implementation jargon as the explanation. Review generated changelogs and replace mechanical entries such as `Merge pull request #N` with a concise user-facing summary.

## Known traps

- Windows shell tray tooltips cap at 127 chars; the real hover popup is our own window fed by `TrayStatus.FullTooltip`.
- PowerShell 5.1 runs the install one-liner: no `RuntimeInformation.ProcessArchitecture`, needs TLS 1.2, and a UTF-8 BOM in `install.ps1` breaks `iwr | iex`.
- `settings.json` is user state at `%LOCALAPPDATA%\costats\settings.json`; app defaults (remote-view URLs, updater) live in `appsettings.json`. Do not write defaults into user state.
- Heredocs and inline scripts on this machine mangle backslashes; write patch scripts to a file and run them.
- The `--screenshot` argument must be quoted (space in the profile path); an unquoted path fails silently.
